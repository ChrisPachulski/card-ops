# Card-Ops -- AI Credit Card Optimization Pipeline

Scaffolded from [santifer/career-ops](https://github.com/santifer/career-ops). See `README.md` for what this does and `AGENTS.md` for agent workflow detail.

## Data Contract (CRITICAL)

Three layers -- know which one you're touching before you write:

- **User Layer** (never auto-updated; personalization goes HERE): `config/profile-chris.yml`, `config/profile-dana.yml`, `config/household.yml`, `modes/_profile.md`, `data/*`, `reports/*`, `statements/*`.
- **System Layer** (auto-updatable, no user data): `lib/*.py`, `modes/_shared.md` and other modes, `CLAUDE.md`, `*.mjs` scripts, `templates/*`, `batch/*`.
- **Data Layer** (generated by lib modules, never manually edited): `data/transactions/*.parquet`, `data/analysis/*.yml`, `data/market/*.yml`.

**RULE:** any user customization (spending categories, reward preferences, issuer priorities) is written to `modes/_profile.md` or the matching config file. NEVER edit `modes/_shared.md` for user-specific content.

## Standing Rules

- Before doing anything else, check onboarding is complete: `config/profile-chris.yml`, `modes/_profile.md`, and `data/cards.md` must all exist. If any is missing, run onboarding -- procedure in `AGENTS.md`.
- Earn rates come ONLY from `lib/card_lookup.py` / `data/known-cards.yml` -- never from the user, memory, or training data. Unknown card: web-search the issuer's page, verify, call `add_card(...)`, then use the looked-up rates.
- `data/known-cards.yml` is generated from wiki articles -- never edit it directly.
- If `wiki/card-ops/cards/` has fewer than 50 articles, or its newest `updated` date is over 30 days old, prompt for a market re-scan -- procedure in `AGENTS.md`.
- NEVER hardcode spending amounts -- read from profiles, `household.yml`, or `data/transactions/*.parquet` at evaluation time. Statement-derived data supplements the profiles; it never replaces them.
- NEVER submit a card application on the user's behalf -- evaluate, score, recommend, then stop. Score below 3.5/5 gets an explicit recommend-against. Guide toward fewer, better cards over churning; flag creditworthiness risk explicitly.
- NEVER edit `data/cards.md` to add new rows -- write a TSV to `batch/tracker-additions/` (format in `AGENTS.md`); `merge-tracker.mjs` merges it in. Editing an existing row's status/notes in place is fine.
- Statuses in `data/cards.md` must be canonical per `templates/states.yml` -- no markdown bold, no dates, no extra text in the status field.
- Report numbering is sequential, 3-digit zero-padded, max existing + 1.
- Health checks: `node verify-pipeline.mjs`, `node normalize-statuses.mjs`, `node dedup-tracker.mjs`.
